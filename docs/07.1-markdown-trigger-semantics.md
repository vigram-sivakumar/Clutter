# File 07.1 — Markdown Trigger Semantics

**Status**: 🔒 LOCKED  
**Scope**: Markdown trigger timing & ownership (not rendering)  
**Version**: 1.0  
**Locked Date**: 2026-02-06  
**Depends On**: File 06, File 06.1  
**Applies To**: All markdown shortcuts (current and future)

---

## 0. Purpose (Why This File Exists)

This document defines **exactly when** markdown shortcuts are allowed to fire and **who wins control** over the DOM.

It exists to prevent a class of bugs where:

- Markdown fires too late
- Browser mutates DOM first
- Prefix cleanup becomes impossible
- Caret behavior becomes unstable

**If markdown triggers after DOM mutation, it is incorrect by definition.**

---

## 1. Core Principle (Non-Negotiable)

### Markdown Is a Pre-Mutation Interception

Markdown shortcuts are **not text transforms**.  
They are **structural intent signals**.

Therefore:

> **Markdown MUST be resolved before the browser inserts characters into the DOM.**

If the browser inserts a space, markdown has already failed.

---

## 2. Ownership Model (LOCKED)

### 2.1 Browser Owns

The browser owns:

- Character insertion
- Space insertion
- IME composition
- Caret movement
- Selection rendering

Unless explicitly intercepted.

---

### 2.2 Editor May Intercept (Strictly Limited)

The editor may intercept **only**:

- The space key (`' '`)
- Only during `keydown`
- Only before DOM mutation
- Only if a valid markdown prefix exists

---

## 3. Trigger Timing (CRITICAL)

### 3.1 Allowed Trigger Point (ONLY ONE)

Markdown MUST be evaluated:

```
keydown(event)
```

**Not allowed:**

- ❌ `input`
- ❌ `beforeinput`
- ❌ `keyup`
- ❌ `selectionchange`
- ❌ async effects
- ❌ React state observers

---

### 3.2 Evaluation Order (Immutable)

On `keydown(' ')`:

1. Read browser selection
2. Read DOM text before caret
3. Compare against exact prefixes
4. Decide:
   - **Intercept** → convert
   - **Or pass through** → browser inserts space

Once step 4 completes, no further markdown logic is permitted.

---

## 4. Source of Truth (LOCKED)

### 4.1 What Markdown May Read

Markdown logic may read **ONLY**:

- `window.getSelection()`
- DOM text inside `.node__content`
- DOM offset calculated via Range API

---

### 4.2 What Markdown Must NOT Read

Markdown logic must **NEVER** read:

- ❌ React state (`editorState`)
- ❌ Stored offsets
- ❌ Cached node text
- ❌ Selection state mirrors
- ❌ Async state updates

**Reason:** Markdown is a race against the browser.  
React state is always too late.

---

## 5. Prefix Matching Rules (STRICT)

### 5.1 Exact Match Only

Markdown triggers **ONLY** when the text before caret is exactly:

| Prefix | Resulting Variant |
| ------ | ----------------- |
| `[]`   | `task`            |
| `-`    | `bullet`          |
| `#`    | `heading-1`       |
| `##`   | `heading-2`       |
| `>`    | `callout`         |

- No partial matches
- No fuzzy matches
- No trailing characters

---

### 5.2 Caret Position Requirement

- Caret must be at end of prefix
- Prefix must start at offset 0

Markdown must **not** trigger in the middle of text.

---

## 6. Interception Rules (MANDATORY)

If a markdown prefix matches:

1. `event.preventDefault()` MUST be called
2. Browser MUST NOT insert space
3. Prefix text MUST be removed from DOM
4. Node variant MUST be converted
5. Caret placement MUST be requested (File 06.1)

**If `preventDefault()` is not called, the implementation is invalid.**

---

## 7. Post-Trigger State Guarantees

After a successful markdown trigger:

- Node text is empty
- Node variant is updated
- Selection is collapsed
- Caret is placed at offset 0
- No stray whitespace exists (`&nbsp;` forbidden)
- No undo entry for prefix typing

---

## 8. Forbidden Outcomes (FAIL CONDITIONS)

Any of the following means markdown is broken:

- `&nbsp;` appears after prefix
- Prefix text remains in DOM
- Variant does not change
- Conversion happens after `input`
- Cleanup occurs in effects
- Caret flickers or jumps
- React state used for detection

**These are architectural violations, not bugs.**

## 10. Validation Checklist (LOCKED)

Markdown is compliant only if **ALL** pass:

### Behavior

- ✅ `[]␣` → task, no prefix, no space
- ✅ `-␣` → bullet
- ✅ `#␣` → heading-1
- ✅ `##␣` → heading-2
- ✅ `>␣` → callout

### DOM

- ✅ No `&nbsp;`
- ✅ No leftover prefix
- ✅ DOM text cleared synchronously

### Architecture

- ✅ Triggered in `keydown`
- ✅ DOM-first detection
- ✅ `preventDefault()` used
- ✅ No React state read

---

## 11. Canonical Statement (LOCK)

> Markdown shortcuts are **pre-mutation intent signals**,  
> not post-mutation text transforms.

> Any implementation that evaluates markdown **after** DOM mutation  
> is considered **invalid**, regardless of user-visible behavior.
