## Evidence and test levels

Use domain/property tests for invariants and merge laws; integration/failure tests
for persistence and IPC; protocol tests for CLI/MCP; browser/native tests for real
input and focus. Avoid tests that merely mirror implementation. Generated action
sequences should cover undo, structural edits, partitions and crash points.

Each run records test ID, fixture, expected result, actual result, environment,
revision, seed/action log, evidence location and pass/fail/blocked status. Skip is
not pass. A patched dependency is a distinct candidate with maintenance evidence.
Every requirement above has at least one matrix reference; this coverage does not
mean all combinations or detailed UI behaviour are already specified.
