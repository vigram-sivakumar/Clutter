## Purpose of This Document

This document defines the exact behavior of Enter and Backspace when the cursor is positioned immediately before or after inline metadata (references, mentions, tags).

**It answers once and forever:**

- Where does inline-meta go when splitting at its position?
- What does Backspace do when cursor is adjacent to inline-meta?
- How does bias determine the behavior?

---

## 1. Core Principle (Non-Negotiable)

### Inline Metadata is Atomic

```
Inline-meta is a single, indivisible unit.
Cursor can be BEFORE it or AFTER it, never INSIDE it.
```

**This means:**
- References cannot be partially selected
- References cannot be partially deleted by character deletion
- References move as complete units during split/merge

---

## 2. Enter Key at Inline Boundaries (LOCKED)

### 2.1 The Rule

**Enter behavior depends on cursor bias:**

```typescript
if (cursor.offset === meta.offset) {
  if (cursor.bias === "before") {
    // Inline-meta goes to AFTER node
  } else {
    // Inline-meta stays in BEFORE node
  }
}
```

**This is the ONLY correct behavior.**

---

### 2.2 Examples

#### Example 1: Cursor Before Reference

**Before:**
```
"Name |@node-8 is vigram"
offset: 4, bias: "before"
```

**After Enter:**
```
Node 1: "Name "
Node 2: |@node-8 is vigram"
         ↑ cursor here, bias: "after"
```

**Why:**
- User visually pressed Enter "before" the ref
- Ref moves to new node
- Text before ref stays in original node
- Cursor lands in new node at offset 0

---

#### Example 2: Cursor After Reference

**Before:**
```
"Name @node-8| is vigram"
offset: 4, bias: "after"
```

**After Enter:**
```
Node 1: "Name @node-8"
Node 2: | is vigram"
         ↑ cursor here, bias: "after"
```

**Why:**
- User visually pressed Enter "after" the ref
- Ref stays in original node
- Text after ref moves to new node
- Cursor lands in new node at offset 0

---

#### Example 3: Cursor Not at Ref Boundary

**Before:**
```
"hello |world"
offset: 6, bias: "after" (doesn't matter)
```

**After Enter:**
```
Node 1: "hello "
Node 2: |world"
```

**Why:**
- No inline-meta at offset 6
- Bias is irrelevant
- Standard split behavior from File 03

---

### 2.3 Multiple Refs at Same Offset

**Before:**
```
"Name |@ref1@ref2 text"
offset: 4, bias: "before"
```

**After Enter:**
```
Node 1: "Name "
Node 2: |@ref1@ref2 text"
```

**Rule:** ALL inline-meta at `cursor.offset` follow the same bias rule.

## 3. Backspace Key at Inline Boundaries (LOCKED)

### 3.1 The Rule

**Backspace at offset 0 (structural merge):**

```typescript
if (cursor.offset === 0) {
  // Always merge with previous node (File 03)
  // Bias doesn't affect this - it's structural
}
```

**Backspace at inline-meta position (character deletion):**

```typescript
if (cursor.offset === meta.offset && cursor.offset > 0) {
  if (cursor.bias === "after") {
    // Delete the character BEFORE cursor (normal backspace)
  } else {
    // Cursor is before inline-meta
    // Delete the character before inline-meta (if any)
  }
}
```

**Note:** Inline-meta deletion is NOT defined in this file. See future File 09 (Inline Actions).

---

### 3.2 Examples

#### Example 1: Backspace After Reference (Normal)

**Before:**
```
"Name @node-8| is vigram"
offset: 4, bias: "after"
```

**After Backspace:**
```
"Name @node-8|is vigram"
         (deleted space before "is")
offset: 4, bias: "after"
```

**Why:**
- Standard character deletion
- Deletes character before cursor
- Reference is untouched

---

#### Example 2: Backspace Before Reference

**Before:**
```
"Name |@node-8 is vigram"
offset: 4, bias: "before"
```

**After Backspace:**
```
"Nam|@node-8 is vigram"
offset: 3, bias: "after"
```

**Why:**
- Cursor is before ref, so backspace deletes "e" (from "Name")
- Reference stays at offset 3 (was 4, adjusted to 3)
- Cursor moves to offset 3, bias resets to "after"

---

#### Example 3: Backspace at Start (Structural)

**Before:**
```
Node 1: "hello"
Node 2: |@node-8 world"
offset: 0, bias: "before"
```

**After Backspace:**
```
Merged: "hello|@node-8 world"
offset: 5 (merge point), bias: "after"
```

**Why:**
- File 03: Backspace at offset 0 = merge
- Bias doesn't change this behavior
- Cursor lands at merge point

## 5. Caret Placement with Bias (LOCKED)

### 5.1 Algorithm

```typescript
function placeCaretWithBias(
  nodeId: NodeID,
  offset: number,
  bias: "before" | "after"
): void {
  const contentEl = document.querySelector(`[data-node-id="${nodeId}"]`);
  
  // Find text node at logical offset (using filtered TreeWalker)
  const { textNode, localOffset } = findTextNodeAtOffset(
    contentEl,
    offset,
    bias
  );
  
  // Place caret in text node
  const range = document.createRange();
  range.setStart(textNode, localOffset);
  range.collapse(true);
  
  const sel = window.getSelection();
  sel.removeAllRanges();
  sel.addRange(range);
}
```

---

### 5.2 Special Case: At Inline-Meta Boundary

**When `offset === meta.offset`:**

```typescript
if (bias === "before") {
  // Place cursor BEFORE the inline-meta span
  // Target: text node immediately before span, at END
} else {
  // Place cursor AFTER the inline-meta span
  // Target: text node immediately after span, at START
}
```

**Never place cursor inside inline-meta span.**

## 7. Edge Cases (Handled)

### Multiple Refs at Same Offset

**Rule:** All inline-meta at the same offset follow the same bias rule.

```
Before: "text|@ref1@ref2@ref3 more"
        offset: 4, bias: "before"

After Enter:
Node 1: "text"
Node 2: |@ref1@ref2@ref3 more"
```

All three refs move together.

---

### Empty Text with Refs

**Before:**
```
Node: "" with ref at offset 0
Visual: |@ref1
offset: 0, bias: "before"
```

**After Enter:**
```
Node 1: ""
Node 2: |@ref1"
```

**Rule:** Even with empty text, bias determines ref placement.

---

### Ref at Start AND End

**Before:**
```
Node: "text" with refs at offset 0 and 4
Visual: @ref1|text@ref2
offset: 0, bias: "after"
```

**After Enter:**
```
Node 1: @ref1
Node 2: |text@ref2
```

**Rule:** Only refs at split point use bias. Others split by offset comparison.
