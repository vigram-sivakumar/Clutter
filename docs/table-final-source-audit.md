### Remaining presentation questions

The production call graph above establishes shared ownership of grammar, token factories, class policy, resolution, activation, completion and preferences. It does not establish universal parity. In particular:

- Static tokenization uses `STYLED_CONTAINER_NODES` and `renderSpan` to choose HTML wrappers while live participants select range decorations. A new construct can still require a projection adapter. Keep shared semantic decisions in the existing owners; do not introduce a third generic renderer or copy new scanners into the table.
- Static `containsProtectedSpan` splits strike around protected descendants using the canonical protected-node set. Live `linkRenderer` uses `linkContentDecorations` over the label range. These are different paint mechanisms. Existing committed tests assert simple four-surface formatted-link parity and static unique strike ownership for a struck link with formatted/code children. The deeper semantic label (bold, tag, date; both engaged and at rest) test reported by Work is not yet in the remote tree. Confirm actual ownership and exact source, activation and strike invariants for that case before declaring final parity. A difference caused only by legitimate live engagement is not a defect. If a true struck-range/child activation gap is reproduced, correct the canonical owner, not a parallel table workaround. Follow `highlight/STRIKETHROUGH.md`.
- Shared configuration does not require identical font sizes, HTML wrappers, caret behaviour, block actions, or read-only interaction. Do not rewrite the table's validated root source transport to force identical DOM.
- Existing tests at this revision cover four-surface formatting, incomplete WikiLink, stored table alias, shared token activation, formatted label navigation, date format refresh and tag refresh. The additional local parity test must be reconciled and the full gate run on the exact final revision.
