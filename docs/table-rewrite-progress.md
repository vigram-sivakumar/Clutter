## Architecture and invariants

- Root CodeMirror 6 owns Markdown, the only persistent source. Read the shared Clutter Lezer grammar to derive one rectangular model with cell source ranges. Reading a note or rendering an absent cell must preserve the source.
- Project a real HTML table using Clutter's inline renderer, CSS classes, alignments, width metadata and scroll container. Preserve mounted cell hosts across updates. Read-only embeds have no editing controls or nested editor.
- One reusable nested CM6 view per editable root, mounted only in the active cell. Forward minimal changes to root; keep typing, composition, focus and native text selection intact.
- One interaction state owns editing, selected cell, rectangle (anchor and head), row, column, whole table and no selection. Validate edits centrally, respect root filters and record selection intent with root history. Each structural action has one undo step; successive typing can group.
- Keep surrounding Markdown intact. Preserve the existing adjacent `{table-col-widths="…"}` syntax and move widths and alignments with their columns. Preserve unsupported input. Use the existing document save path.

**Architecture status.** The implementation adds no persistence or history owner. Editable controls still use several legacy selection fields during migration to the agreed single interaction state.

**Migration gaps.** M4 supports present imported cells with arbitrary padding. Activating an absent cell formats the addressed table through one reversible engine transaction, which can canonicalize its padding. Structural engine commands currently serialize the addressed table, so an edit can canonicalize source padding. Active source spans preserve typed spaces. External edits overlapping that span end editing. History shortcuts end editing before root undo/redo. The compatibility renderer handles source outside the engine's supported shape. Unsupported clipboard structures include merged cells and oversized grids. Full application regression, native IME and production manual acceptance are outstanding.

**Legacy inventory.** The new projection replaces static rendering for supported read-only tables. M2 replaces whole-table deletion dispatch while retaining its existing keyboard and menu entry points. Keep `tableWidget.ts`, `tableWidgetField.ts`, `tableActiveCellController.ts`, legacy selection fields, keymaps, structural commands, overlays and tests through the gates above. Inline rendering, shared grammar, width syntax, CSS and breakout measurement remain shared dependencies. No legacy subsystem has been removed.


## M4 manual validation

M4 is available through `BuildEditorExtensionsOptions.tableEngineCells: true`, or the development URL parameter `?tableEngineCells`. This is an explicit rollout choice. Default editable controls continue to use the previous implementation until selection, clipboard, menus and drag parity are integrated. The new cell projection currently provides activation and text editing. At M4, prototype rectangular drag, auto-scroll and caret-free Tab/Escape behavior were outstanding; M5 subsequently added keyboard interaction. This limitation prevents default rollout.

**Caret failure and resolution.** The root editor installs `drawSelection()`. Its scoped theme hides native carets on descendant `.cm-content` and `.cm-line` elements, including nested editors. M4 created a focused nested CM6 view with only a keymap, leaving its native caret transparent and no drawn cursor layer to replace it. The prototype explicitly installed `drawSelection()` in its nested editor. The fix installs that same CM6 primitive. Root caret suppression uses direct-child selectors and therefore does not suppress the nested cursor layer. Existing Clutter cursor colors apply to the drawn caret. No CSS change or legacy controller dependency was required.
