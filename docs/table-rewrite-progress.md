## Architecture and invariants

- Root CodeMirror 6 owns Markdown, the only persistent source. Read the shared Clutter Lezer grammar to derive one rectangular model with cell source ranges. Reading a note or rendering an absent cell must preserve the source.
- Project a real HTML table using Clutter's inline renderer, CSS classes, alignments, automatic intrinsic sizing and scroll container. Preserve mounted cell hosts across updates. Read-only embeds have no editing controls or nested editor.
- At most one live nested CM6 view per editable root, mounted only in the active cell (M11 diagnostic candidate restores prototype's per-activation destruction). Forward minimal changes to root; keep typing, composition, focus and native text selection intact.
- One interaction state owns editing, selected cell, rectangle (anchor and head), row, column, whole table and no selection. Validate edits centrally, respect root filters and record selection intent with root history. Each structural action has one undo step; successive typing can group.
- Keep surrounding Markdown intact. Recognise valid adjacent legacy `{table-col-widths="…"}` syntax without displaying or applying it; preserve on open, remove atomically on a real supported-table edit, restore on undo. Preserve unsupported input. Use the existing save path with exact Markdown persistence (no automatic table formatting in staged mode).

### Historical architecture notes (M4 snapshot)

**Architecture status.** The implementation adds no persistence or history owner. Editable controls still use several legacy selection fields during migration to the agreed single interaction state.

**Migration gaps.** M4 supports present imported cells with arbitrary padding. Activating an absent cell formats the addressed table through one reversible engine transaction, which can canonicalize its padding. Structural engine commands currently serialize the addressed table, so an edit can canonicalize source padding. Active source spans preserve typed spaces. External edits overlapping that span end editing. History shortcuts end editing before root undo/redo. The compatibility renderer handles source outside the engine's supported shape. Unsupported clipboard structures include merged cells and oversized grids. Full application regression, native IME and production manual acceptance are outstanding.

**Legacy inventory.** The new projection replaces static rendering for supported read-only tables. M2 replaces whole-table deletion dispatch while retaining its existing keyboard and menu entry points. Keep `tableWidget.ts`, `tableWidgetField.ts`, `tableActiveCellController.ts`, legacy selection fields, keymaps, structural commands, overlays and tests through the gates above. Inline rendering, shared grammar, width syntax, CSS and breakout measurement remain shared dependencies. No legacy subsystem has been removed.

### WikiLink table aliases — design decision and outstanding integration

Owner explicitly approved automatic escaping and prioritised solid architecture. Adopt the GFM-compatible table storage convention used by Obsidian: users type a pipe inside a WikiLink alias; on disk the alias separator is escaped for the table layer. GFM spec §4.10 (https://github.github.com/gfm/#tables-extension-), Lezer's Table implementation (https://github.com/lezer-parser/markdown/blob/main/src/extension.ts), and Obsidian's documented alias syntax (https://obsidian.md/help/advanced-syntax) support the choice. No library-maintainer recommendation specific to Clutter's custom WikiLink grammar was found. Lezer's documented InlineContext has no enclosing block-kind property. Do not globally redefine the existing scanner's literal escaped-pipe semantics: ordinary prose must keep its existing meaning. The storage adapter and contextual reader need exact offset mapping, including backslash parity, malformed/in-progress links, multiple pipes and literal pipes in names/aliases; preserve Lezer's Table parser and validated root transaction stream. The ingest LinkExtractor currently uses an independent regex, so escaped aliases cannot be considered complete until extraction, search, rename/move rewrite and display use the same contextual semantics. Validate cache/parser-version implications of any ingest grammar change. No parser fork, silent migration or relaxed validation; completion acceptance must not create a target if the root transaction is rejected. This is an integration design constraint, not a claim that alias support is already implemented.
