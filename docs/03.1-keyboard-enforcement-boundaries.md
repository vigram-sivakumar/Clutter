## Purpose of This Document

File 03.1 exists to permanently prevent keyboard regressions.

It answers—once and forever:

- Which keys are browser-owned
- Which keys the editor may intercept

- What keyboard handling is forbidden by definition

## 0. Prime Directive (Non-Negotiable)

### Keyboard Ownership Is Binary

For every keypress, **exactly one owner** exists:

> **Browser-owned** OR **Editor-owned**

There is no shared ownership, no fallback, no hybrid logic.

**If the editor intercepts a key:**

- The browser must be fully blocked
- The editor must fully handle the outcome

**If the browser owns a key:**

- The editor must not interfere
- No `preventDefault()`
- No manual caret movement
- No state-driven simulation

---

## 1. Browser-Owned Keys (ABSOLUTE)

The following keys are **100% browser-owned** in all non-exception cases.

### 1.1 Text Navigation (Horizontal)

| Key        | Ownership | Notes                     |
| ---------- | --------- | ------------------------- |
| ArrowLeft  | Browser   | Includes shift+ArrowLeft  |
| ArrowRight | Browser   | Includes shift+ArrowRight |
| Home       | Browser   | Line start                |
| End        | Browser   | Line end                  |

**Forbidden:**

- ❌ `preventDefault()`
- ❌ Manual offset updates
- ❌ Manual caret sync
- ❌ State-driven navigation

**Rationale:**  
These keys operate within text, not structure. The browser already does this perfectly.

---

### 1.2 Text Input

| Input                           | Ownership |
| ------------------------------- | --------- |
| Character keys (a–z, symbols)   | Browser   |
| Space (unless markdown trigger) | Browser   |
| IME composition                 | Browser   |
| Dead keys                       | Browser   |

**Rules:**

- Browser inserts text
- Editor observes via `input`
- Editor mirrors state later
- Editor never inserts characters manually

---

### 1.3 Mouse-Derived Keyboard States

| Action                  | Ownership |
| ----------------------- | --------- |
| Shift + Arrow selection | Browser   |
| Ctrl/Cmd + Arrow        | Browser   |
| Double / triple click   | Browser   |

## 2. Editor-Owned Keys (STRUCTURAL)

The editor may intercept **only** keys that change document structure.

### 2.1 Enter

**Ownership:** Editor

**Allowed:**

- `preventDefault()`
- Snapshot selection
- Apply intent
- Commit mutation
- Explicit caret placement (File 06.1)

**Cases (from File 03):**

- Start → create sibling above
- Middle → split
- End/empty → create sibling below

---

### 2.2 Backspace / Delete

**Ownership:** Editor

**Allowed:**

- `preventDefault()`
- Selection deletion
- Node merge
- Node deletion
- Caret placement after merge/delete

**Forbidden:**

- ❌ Outdent
- ❌ Structural changes beyond delete/merge

---

### 2.3 Tab / Shift+Tab

**Ownership:** Editor

**Allowed:**

- Indent / outdent
- Preserve offset
- Explicit caret placement

---

### 2.4 ArrowUp / ArrowDown

**Ownership:** Editor

**Why:** Vertical navigation crosses node boundaries.

**Allowed:**

- `preventDefault()`
- Compute target node
- Compute best visual offset
- Explicit caret placement

**Forbidden:**

- ❌ Manual horizontal offset changes
- ❌ DOM mutation beyond caret placement

---

## 3. Boundary-Only Interception (CRITICAL)

Some browser-owned keys may be intercepted **only** at structural boundaries.

### 3.1 ArrowLeft Boundary Rule

Editor MAY intercept **only if:**

```
offset === 0
AND selection is collapsed
AND action is structural (collapse / jump)
```

**Otherwise:**

- Browser owns the key
- Editor must return immediately

---

### 3.2 ArrowRight Boundary Rule

Editor MAY intercept **only if:**

```
offset === endOfNode
AND selection is collapsed
AND action is structural (expand / jump)
```

---

### 3.3 Mandatory Early Return Pattern

```javascript
if (e.key === 'ArrowLeft') {
  if (offset !== 0 || e.shiftKey) return; // browser
  // structural handling
}
```

**Any other pattern is invalid.**

## 4. Markdown Exception (Cross-Referenced)

Markdown interception is governed by:

- **File 07.1** — Trigger Semantics
- **File 07.2** — Consumption & Undo

### Summary Rule

- Markdown is intercepted only on `keydown`
- Only when trigger pattern + space is detected
- Only via DOM truth (not React state)
- Only one mutation + one caret placement

**Markdown never changes keyboard ownership rules.**

## 6. Forbidden Patterns (ABSOLUTE)

The following are **constitutionally forbidden**:

- ❌ Simulating text insertion
- ❌ Manual offset math for horizontal movement
- ❌ React state–driven caret movement
- ❌ Keyboard logic inside `useEffect`
- ❌ Keyboard logic based on stale editor state
- ❌ "Fixing" browser behavior
- ❌ Special casing variants

**Violations must be deleted, not patched.**
