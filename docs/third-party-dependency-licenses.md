# Production dependency licences

Reviewed on 25 November 2026 against application revision `65d8add6`.

The [inventory](third-party-dependency-inventory.json) contains 284 Rust crate versions, 54 npm package versions and three bundled fonts. The Rust inventory uses the union of normal dependency graphs for `aarch64-apple-darwin` and `x86_64-apple-darwin` from the locked Cargo graph. Intel additionally includes `core_detect`. Normal graph traversal includes proc macros and other compile-time contributions. The npm inventory follows the installed, locked production dependency closure of `apps/app`, including packages whose code the bundler may remove. PDF.js optional Node-only canvas and path2d adapters are excluded from its browser build. Development tools and server-side Worker dependencies are outside this application redistribution inventory.

The common app bundle now includes `Contents/Resources/Licenses/THIRD-PARTY-NOTICES.txt`. It lists each component, declared licence, exact source archive URL and the SHA-256 of each included licence or attribution text. Identical texts are shared by digest. All available packaged licence, copyright, author and NOTICE files are retained, including nested notices in ring and PDF.js. The existing individual font and PDF.js notices remain packaged. Direct-distribution builds additionally package the official Sparkle 2.10.1 SDK licence.

Some published Rust crates omit their repository-level licence files. For the objc2 family, UNIC and alloc-stdlib, the missing texts were retrieved from the exact Git revisions in the crates' `.cargo_vcs_info.json`. The inventory records those immutable upstream URLs. The objc2 repository supplies a licensing overview with links to the standard terms. The inventory retains that overview, the declared authors and the MIT permission terms. Selectors retains its source licence header and the complete MPL-2.0 text.

Five crates declare MPL-2.0: cssparser, cssparser-macros, dtoa-short, option-ext and selectors. The acknowledgements identify their unmodified source and provide exact source download links. Recipients can obtain those sources under MPL-2.0. Mozilla describes this source-availability obligation for compiled, unchanged components in its [MPL FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/#q8-i-want-to-distribute-outside-my-organization-executable-programs-or-libraries-that-i-have-compiled-from-someone-elses-unchanged-mpl-licensed-source-code-either-standalone-or-part-of-a-larger-work-what-do-i-have-to-do).

To refresh the inventory after dependency changes, resolve both locked platform graphs with `cargo tree --locked --target <target> --edges normal` and `cargo metadata --locked --filter-platform <target> --format-version 1`. Traverse production npm dependencies from the app manifest using the installed package locations, verify their versions against the lockfile, collect the package licence and notice files, and retrieve omitted texts only from the exact source revision. Update the inventory, source links, text digests and bundled acknowledgements together. Rebuild the app and compare the packaged file with the checked-in source.

This review found missing redistribution notices and supplied them without changing dependency versions. Recheck this inventory whenever production dependencies or bundled assets change.
